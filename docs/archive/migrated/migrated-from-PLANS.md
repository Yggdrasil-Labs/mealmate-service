# 执行计划说明

## 作用

执行计划回答"接下来怎么做"，将需求和设计转化为可执行的分步任务，并跟踪实施进度和技术债。

## 主入口

- [进行中的执行计划](./exec-plans/active/README.md)
- [已完成执行计划](./exec-plans/completed/README.md)
- [技术债追踪](./exec-plans/tech-debt-tracker.md)

## 执行计划的生命周期

1. **创建阶段**：基于产品规格或设计文档创建执行计划，放入 `active/`
2. **执行阶段**：按计划逐步实施，更新任务状态
3. **完成阶段**：完成后归档到 `completed/`，记录最终结果和未完成项
4. **债务跟踪**：发现的技术债记录到 `tech-debt-tracker.md`

## 执行计划应包含的内容

- **目标**：明确要达成什么
- **范围**：明确做什么和不做什么
- **架构**：说明技术方案和分层策略
- **任务分解**：将目标拆分为可验证的小步骤
- **涉及文件**：列出需要创建或修改的文件
- **验证方式**：说明如何验证每个任务完成
- **状态更新**：记录当前进度和遇到的问题

## 与其他文档的关系

- **产品规格**（`product-specs/`）：提供需求输入
- **设计文档**（`design-docs/`）：提供设计约束
- **执行计划**（`exec-plans/`）：将需求和设计转化为实施步骤
- **技术债**（`tech-debt-tracker.md`）：记录暂不处理的问题

## 命名约定

建议使用以下格式：

```
YYYY-MM-DD-<topic>-<type>.md
```

例如：
- `2026-04-16-uc2-recipe-design.md`
- `2026-04-16-uc2-recipe-implementation-plan.md`

## 编写建议

- 任务粒度适中，每个任务 1-2 小时可完成
- 任务之间有清晰的依赖关系
- 每个任务有明确的验证标准
- 使用 `./mvnw` 命令验证构建和测试
- 记录遇到的问题和解决方案
- 完成后及时归档，避免 `active/` 堆积过多文件

## 技术债管理

技术债应记录：
- 发现日期
- 问题描述
- 影响范围
- 建议动作
- 当前状态

不应立即处理的技术债：
- 不影响当前需求交付
- 需要更大范围的重构
- 需要更多信息才能决策
- 优先级低于当前任务
