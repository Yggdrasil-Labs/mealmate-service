# 产品规格：UC3 生成周计划

## 问题与动机

MealMate 的核心价值在于自动化家庭饮食规划。当前系统已具备家庭画像管理（UC1）和菜品库管理（UC2），但缺少将两者串联为具体用餐安排的核心能力。用户仍需手动决定每天三餐吃什么，无法利用已录入的家庭偏好和菜品数据自动生成合理的一周计划。

## 目标用户

- 家庭饮食负责人（通常是妻子/丈夫），需要每周规划全家三餐。
- 有特殊饮食约束的家庭（如有宝宝、减脂成员）。

## 功能边界

**做什么（In Scope）**：
- 用户手动触发生成指定周的 7×3 餐用餐计划
- 系统根据家庭画像约束（忌口/过敏过滤、不重样、减脂餐分布、宝宝适配、季节推荐、湘味偏好、烹饪时长）从菜品库筛选排布
- 用户可在草稿状态下替换、添加、删除餐次菜品
- 用户可手动按菜名添加（模糊匹配已有菜品，匹配不到则创建草稿菜品）
- 用户确认计划（状态从 DRAFT → CONFIRMED）
- 确认后自动派生备菜计划（PrepPlan）与采购清单（ShoppingList）
- 查看当前周/指定周的计划详情
- 查看备菜计划、更新备菜任务状态
- 查看采购清单、标记已采购
- 前端新增"周计划"页面（7×3 网格视图 + 操作能力）
- 前端新增"备菜计划"页面和"采购清单"页面

**不做什么（Out of Scope）**：
- 定时自动生成计划
- 历史计划数据参与生成的去重优化
- 多家庭切换
- CONFIRMED 状态回退到 DRAFT

## 用户场景

### 场景 1：生成周计划

1. 用户进入"周计划"页面，选择目标周（默认下一周）
2. 用户点击"生成计划"按钮
3. 系统检查该周是否已有 CONFIRMED 计划（有则拒绝，提示已确认）
4. 系统根据家庭画像约束 + 菜品库，自动填充 7 天 × 3 餐（早餐 1 道，午/晚餐各 2 道）
5. 系统覆盖该周已有的 DRAFT 计划（如有）
6. 用户看到生成的计划网格，状态为 DRAFT

### 场景 2：手动调整计划

1. 用户查看 DRAFT 状态的周计划
2. 用户点击某个餐次中的菜品，选择"替换"
3. 系统展示可替换的菜品列表（已过滤忌口/宝宝约束）
4. 用户选择新菜品，系统替换并校验不重样
5. 用户也可在某餐次中"添加"新菜品，或"删除"已有菜品（至少保留 1 道）

### 场景 3：确认计划

1. 用户审阅计划后点击"确认"
2. 系统将计划状态改为 CONFIRMED，锁定编辑
3. 系统自动派生备菜计划（PrepPlan）与采购清单（ShoppingList）
4. 用户可跳转查看备菜计划或采购清单

### 场景 4：查看计划

1. 用户进入周计划页面
2. 系统展示当前周的计划（若有）
3. 用户可切换到其他周查看历史计划

## 输入与输出（用户视角）

| 方向 | 用户提供/看到什么 | 约束（用户可感知的） |
|------|-------------------|---------------------|
| 输入 | 目标周的起始日期 | 必须是周一日期（生成接口限未来周，查看接口允许历史周） |
| 输入 | 替换/添加时选择的菜品 | 只能选已通过约束校验的菜品 |
| 输出 | 7×3 网格计划视图 | 每格显示菜品名称列表，标注餐次类型 |
| 输出 | 计划状态标识 | DRAFT/CONFIRMED/ARCHIVED |

## 验收标准

- [ ] Given 家庭有 ≥1 个成员且菜品库有 ≥15 道菜, When 用户点击生成计划, Then 系统成功生成 7×3 餐的计划且所有菜品通过硬约束校验
- [ ] Given 计划状态为 DRAFT, When 用户替换某餐次菜品, Then 新菜品替换旧菜品且 7 天内无重复
- [ ] Given 计划状态为 DRAFT, When 用户添加某餐次菜品, Then 菜品追加到该餐次列表
- [ ] Given 计划状态为 DRAFT, When 用户删除某餐次唯一菜品, Then 系统拒绝删除
- [ ] Given 计划状态为 DRAFT, When 用户确认计划, Then 状态变为 CONFIRMED 且不可编辑
- [ ] Given 该周已有 CONFIRMED 计划, When 用户尝试重新生成, Then 系统拒绝并提示
- [ ] Given 该周已有 DRAFT 计划, When 用户重新生成, Then 覆盖旧 DRAFT

## 异常与边界情况

| 场景 | 触发条件 | 预期行为 |
|------|----------|----------|
| 菜品库不足 | 菜品数量不够填满 7×3 餐次 | 提示"菜品库不足，请先添加更多菜品" |
| 无家庭成员 | familyId 下无成员数据 | 提示"请先完善家庭画像" |
| 宝宝菜品不足 | 有宝宝成员但宝宝适配菜品不够 | 允许生成但标记缺口，提示用户手动补充 |
| 重复生成覆盖 | 同周已有 DRAFT | 静默覆盖，保留最新生成结果 |

## 产品约束

- 同一家庭同一周只能有一份有效计划（DRAFT 或 CONFIRMED）
- 状态流转：DRAFT → CONFIRMED → ARCHIVED，不支持回退
- 生成算法采用完整规则体系（R-01~R-07），强制规则必须满足，偏好规则尽力满足后逐级降级放宽
- 默认菜品数：早餐 1 道，午/晚餐 2 道

## 度量与成功标准

- 生成成功率 ≥ 95%（在菜品库充足的前提下）
- 生成耗时 < 2s
- 用户手动调整率作为后续算法优化参考指标
